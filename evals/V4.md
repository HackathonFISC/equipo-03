## Sondeos HTTP

`caja_negra.py` permite adaptar peticiones sin editar código de Noel. El perfil
local tiene `base_url` y una lista `guiones`. Cada guion incluye `id` y `pasos`.
Cada paso contiene `nombre` único, `metodo` (`GET`/`POST`), `ruta` relativa,
`cuerpo` opcional, `esperado` con `http` y `json` (mapa JSON Pointer → valor).
`capturar` guarda el hash de un campo para compararlo posteriormente mediante
`esperado.igual_a_captura`. Campos ausentes no equivalen a null.

Ejemplo **de formato**, con rutas ficticias que no existen en la API del equipo:

```json
{
  "base_url": "http://localhost:8000",
  "guiones": [{
    "id": "sondeo-version",
    "pasos": [{
      "nombre": "rechazo",
      "metodo": "POST",
      "ruta": "/RUTA_POR_ACORDAR",
      "cabeceras_entorno": {"Authorization": "V4_AUTORIZACION_ENSAYO"},
      "cuerpo": {"version": 1},
      "esperado": {"http": 409, "json": {"/codigo": "version_obsoleta"}}
    }]
  }]
}
```

Ese ejemplo incompleto no acredita el caso 20: agregar controles positivos y
lecturas de auditoría con capturas antes/después. La ruta inexistente falla,
nunca cuenta como rechazo válido. `cabeceras_entorno` lee el valor COMPLETO de
la cabecera del entorno (por ejemplo, Bearer seguido del token); no guardarlo en
archivos versionados. No publicar perfiles con texto ciudadano, chat IDs ni
datos personales. Usar identidades y cuerpos sintéticos de ensayo.

Con un perfil acordado, y solo sobre el entorno de prueba previsto:

```powershell
.\.venv\Scripts\python.exe -m evals.ejecutar --salida ../tmp/evaluacion_v4_http_01 --perfil-http ../tmp/perfil_v4_local.json
```

Sin reintentos, redirecciones ni lectura de `.env`; HTTPS obligatorio fuera de
localhost. La evidencia conserva nombres de pasos, método, estado HTTP y número
de comprobaciones; no conserva cuerpos, tokens, URL ni respuestas crudas. El
perfil permanece local y los casos oficiales siguen pendientes hasta revisión
conjunta de su evidencia. El ejecutor no implementa un adaptador concurrente.
